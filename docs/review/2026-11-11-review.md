# Arbiter review, 2026-11-11

Review of commit f406488 (integration I1 and I2). The fixes are in the commit "fix: address ultracode review findings".

## Lenses

The review used six finder lenses, each reading the code against docs/DESIGN.md (with its Decisions log), the build plan and the lane notes, and probing the running system:

- sandbox: sandbox and judge security and robustness.
- authapi: authentication, authorization and API security.
- contest: contest, scoreboard, rating and plagiarism correctness.
- data: data model, performance and reliability.
- frontend: frontend UX, accessibility and client-side security.
- spec: spec conformance, completeness and test quality.

Findings were then verified through three verification lenses: reality, intent and impact. Critical and high findings got all three votes (majority wins). Medium findings got reality and intent, with impact breaking a tie. Low findings got batched reality-and-intent votes.

Fixes were made by area (the fix areas, not lenses), and the fixes were reviewed by two Opus reviewers (back end and web):

- api: auth and sessions, RBAC, validation and rate limits, contests, scoreboard, rating, plagiarism, realtime, query efficiency, test coverage.
- judge: sandbox and harness, queues and workers, janitor, checkers, failure handling, test coverage.
- web: error and loading states, accessibility (focus, live regions, contrast), routing and query-string handling, admin editors, e2e coverage.
- shared: schemas, pagination bounds, score encoding, database indexes, scripts.
