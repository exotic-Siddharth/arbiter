## Integration needs

- API (lane A3b): the contest workspace fetches `GET /api/contests/:slug/problems/:label` and parses it with `ProblemDetailSchema`, plus `GET /api/contests/:slug` with `ContestDetailSchema` for the header; the endpoint must return the problem detail shape and enforce contest visibility.
- API (runs): Run posts `POST /api/runs` with `CreateRunBody` including `problemSlug` (R11) and parses `CreateRunResponseSchema`; the result comes from the `run:result` socket event with a `GET /api/runs/:id` poll as fallback. Both routes and the event must exist with those shapes.
- API (lane A3a): the problem list sends `search, difficulty, tag, status, sort, page, pageSize` and renders `acceptanceRate` and `userStatus` (SOLVED / ATTEMPTED / null) of each summary; `GET /api/tags` must match `TagListSchema` for the tag select.
- API (lane A3a): the submission list sends `mine=true` (only when signed in), `problem`, `verdict`, `language`, `username`, `page`, `pageSize`; the API must accept `mine=true` as the boolean flag.
- API (lane A3a): `GET /api/submissions/:id` must return no source for non-owners who are not admins; the detail page then shows a "Source code hidden" state.
- Realtime (lane A5): the workspace and the pending rows of the submissions table join `useRoom('submission:subscribe', { id })` and listen to `submission:status`, `submission:test` and `submission:done`; the server must emit these to the submission room with the shared payload schemas.
- Visual check used mocked API data only; repeat the screenshots against the real seeded API once seed.ts exists.

## Decisions

- 2026-11-08: Live submission progress merges REST and socket state (`features/problems/lib/progress.ts`) so a refetch never moves the UI backwards; while a submission is pending its detail query also polls (8 s with the socket connected, 2 s without) so a lost socket never leaves an endless spinner (R6: REST is the source of truth).
- 2026-11-08: Editor drafts live in localStorage under `arbiter:draft:<problemSlug>:<language>`; switching language loads that language's draft or the template, and resetting to the template asks for confirmation when the draft differs.
- 2026-11-08: After the first failing test, the remaining test chips stay neutral ("not run") rather than being marked skipped, matching the judge's stop-on-first-failure behaviour.
- 2026-11-08: The submission-detail test-results table uses fixed-width time and memory columns so the numbers sit together on wide screens.
