## Integration needs
- API register 409 (A1): the web maps a 409 onto the field named in `error.details.field` ("email" or "username"); without it, it guesses from the message (contains "email" means the email field, otherwise username). Have POST /api/auth/register return `details: { field: 'email' | 'username' }` with the 409.
- Landing feed seed: there is no REST feed endpoint, so the landing page seeds the feed from `GET /api/submissions?pageSize=10` (all users, newest first) and keeps only items with `status === 'DONE'`, a verdict and no `contestSlug`. A3a's list must allow guests to read it, and must not expose in-window contest submissions (spec 9); otherwise a dedicated endpoint is needed.
- Landing queries `GET /api/contests?status=running` and, if empty, `?status=upcoming` (A3b); both must work for guests.
- `GET /api/users/:username` must answer 404 for an unknown user (the profile page shows a "No such user" state) and be case-insensitive on the username.
- `VITE_DEMO_LOGIN=true` must be set in apps/web/.env for the "Try the demo" buttons (hero, login, register); they call `useAuth().loginDemo()` (POST /api/auth/demo).
- Not mocked anywhere: everything is wired to the real endpoints named above; all pages were only exercised against fixtures (unit tests and Playwright route mocks), never against the live API.

## Decisions

The list is capped at 12 items, de-duplicated on username, problem and timestamp, newest first.
- 2026-11-08: The featured contest is the first running contest, else the earliest upcoming one (two list queries, the second only when no contest is running).

- 2026-11-08: Login and register validate with the shared zod schemas (LoginBody, RegisterBody) on blur and submit; server field errors from fieldErrors() are merged onto the fields; a 409 shows inline on the conflicting field; other failures show an Alert.
- 2026-11-08: Heatmap is an SVG grid of 365 cells (one hue in five steps from the primary colour mixed into the surface, theme-aware through CSS variables); one tab stop with arrow-key navigation (left/right move a week, up/down a day), tooltip on hover and focus, every cell has a text label, legend shows 0 to the busiest day.
- 2026-11-08: RatingChart uses recharts: x axis is the contest sequence (Start, #1..#n) instead of a time axis so evenly spaced contests are readable; faint tier bands carry the tier names as text; a "Show table" toggle gives the same data as a table.

- 2026-11-08: The profile page skips <Page> (own container, own h1 with the avatar) and sets the document title through useDocumentTitle(username).
